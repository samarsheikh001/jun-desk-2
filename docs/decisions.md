## Open questions

### D-06 — Product name and positioning line
- Working name "Jun Desk". Positioning draft: *"Open-source AI support desk for B2B SaaS. Deploy to your own Cloudflare account in one click."*

### D-10 — Default LLM provider
- Workers AI works with zero keys (best one-click experience) but answer quality is lower.
- Claude via BYO Anthropic key gives the best quality; prompted as a secret at deploy.
- **Leaning:** support both; setup wizard recommends Claude Sonnet 5.5, falls back to Workers AI if no key. *(proposal)*
- **2026-10-04 — user wants ChatGPT/OpenAI.** "Login with ChatGPT" isn't viable for the live agent (see `research/06-chatgpt-login.md`). Proposal: OpenAI via API key as a provider, routed through Cloudflare AI Gateway. Open: is OpenAI the default, or one option among Claude / OpenAI / Workers AI? Also: use "Sign in with ChatGPT" for the local eval CLI (`jun eval`)?

### D-13 — Slack implementation details
- Each self-hosted install needs its **own Slack app** (OAuth credentials can't be shared across installs). Plan: bundled app manifest + guided setup (T-13).
- **Verified 2026-10-03:** Slack Connect requires a **paid Slack plan on both sides**: "each organisation must be using a paid Slack subscription" ([Slack help](https://slack.com/help/articles/115004151203-A-guide-to-Slack-Connect)). Free-plan orgs can only be invited to *try* Slack Connect temporarily. Fine for most B2B SaaS teams and customers, but customers who aren't on paid Slack need the widget/email instead.
- To verify: Slack's 2025 rate limits on `conversations.history` for non-Marketplace *commercially distributed* apps. Internal/custom apps (which is what self-hosters create) are believed to be exempt *(unverified)*.
- Decided connection modes: see log entry D-13 (2026-10-03).

- **2026-10-04 — Repo layout: the deployable Worker lives at the repo root** (`wrangler.jsonc`, `src/`). `packages/` holds the widget, SDK, llm and cli, which build into the Worker's static assets. Satisfies the deploy button's self-contained rule.
- **2026-10-04 — All v1 features agreed.** v1 is locked as in `build-plan.md` (45 launch-critical, 11 can slip to v1.1).
- **2026-10-04 — D-17 — Passkeys for login.** Magic links need an email service (a verified domain) and Google login needs OAuth keys, both of which break one-click deploy. The owner is created on first visit using a `SETUP_TOKEN` secret the deploy button prompts for; the same token recovers owner access. Agents join through invite links. Magic link, Google and SSO can be optional add-ons later.
- **2026-10-04 — D-18 — Vector search in a Durable Object, not Vectorize.** Wrangler doesn't auto-provision Vectorize indexes (needs dimensions) and Vectorize has no local simulation, which breaks one-click deploy and local dev. Each workspace's `KnowledgeIndex` DO stores int8-quantized bge-m3 embeddings in its SQLite and searches in memory (fine to tens of thousands of chunks). Combined with D1 FTS5 keyword search and a reranker. Vectorize can become an optional scale mode later.
- **2026-10-04 — D-10 (update) — Provider defaults as built.** Workers AI (`@cf/openai/gpt-oss-120b`) is the zero-key default, so a fresh deploy answers with no API key. OpenAI via `OPENAI_API_KEY` Worker secret (optionally through AI Gateway with `OPENAI_BASE_URL`). ChatGPT sign-in works in the dashboard only when `JUN_DEV_CHATGPT=1` and on a loopback host. Release default still the user's call (proposal: keep Workers AI as default, recommend OpenAI/Claude key for quality).
- **2026-10-04 — D-19 — Debug capture is minimal and masked by default.** The loader keeps a 40-event in-memory buffer (errors, failed requests, navigation), never writes to storage, never captures request/response bodies, strips query values, and masks emails/tokens/keys/secrets/card-like numbers. It sends the snapshot only when the visitor sends a message; the server sanitizes it again. Sites can disable it with `data-capture="off"`. Session replay (S-04) stays out of v1.
- **2026-10-04 — D-20 — The AI can answer *and* escalate.** Besides `HANDOFF` (can't answer), the model may end a reply with `ESCALATE: <summary>` when browser errors explain the problem: the visitor gets the explanation, then the conversation goes to the team with a brief that quotes the failing request. Both control lines are filtered out of the stream so visitors never see them.
- **2026-10-04 — D-21 — "More reactive" (user request).** (1) The AI tries before handing off: one clarifying question or safe generic steps when knowledge doesn't cover it; still hands off for staff-only actions, explicit requests, frustration, or when still stuck. Never invents company facts. (2) Proactive nudge when the page has a real error (S-06 pulled into v1), on by default with a toggle. (3) Speed: typing dots shown instantly in the widget, parallel lookups in the AI turn, reranker skipped for small candidate sets, and the default Workers AI model switched to `@cf/meta/llama-3.3-70b-instruct-fp8-fast` (0.6–0.9 s to first word vs 1.8–3.8 s for gpt-oss-120b; see `scripts/bench-models.ts`).
- **2026-10-05 — D-22 — Agent engine: borrow the AI SDK, keep our support logic (user: "letsgo").** Options compared as of 2026-10-05: Vercel AI SDK (`ai` 7, [tools](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)), `workers-ai-provider` 4 ([Cloudflare docs](https://developers.cloudflare.com/workers-ai/configuration/ai-sdk/)), Cloudflare Agents SDK skills engine ([docs](https://developers.cloudflare.com/agents/runtime/execution/agent-skills/)), Cloudflare Think ([docs](https://developers.cloudflare.com/agents/harnesses/think/)), and coding-agent harnesses (Codex, Claude Agent SDK). Decided after a spike:
  - **Model calls and the tool loop use the AI SDK** (`streamText` + `isStepCount(5)`), with `workers-ai-provider` and `@ai-sdk/openai` (the dev-only ChatGPT sign-in goes through `@ai-sdk/openai` with a token-refreshing `fetch`). Our `Conversation` DO, knowledge search, debug context, HANDOFF/ESCALATE, citations, handoff brief and caps stay ours. One engine (`worker/ai/run.ts`) serves live chats and evals.
  - **Spike finding:** Workers AI streams most chat models in two shapes at once (`choices[0].delta` *and* legacy `response`/`tool_calls`), and `workers-ai-provider` 4.0 reads both, so text and tool-call arguments arrived twice ("II am am", broken JSON). `worker/ai/workers-ai.ts` wraps the binding to drop the legacy copies. Worth reporting upstream.
  - **Not used:** Think (you must extend its Durable Object class, which would replace M1–M4's realtime layer; parts still experimental); `agents/skills` (imports a code sandbox and bash emulator to run skill scripts; a support agent never runs scripts, so a small `SKILL.md` loader of our own instead); coding-agent harnesses (need a machine and a shell).
  - **Config format (MIT):** `AGENTS.md` (persona, rules; frontmatter `maxReplies`, `handoffTopics`) + `skills/<name>/SKILL.md` (Agent Skills format: `name`, `description`) + `tools/<name>.yaml` (HTTP lookups: GET/POST, `{input}` placeholders, `{secrets.NAME}` from Worker secrets `JUN_SECRET_NAME`, headers only) + `evals/<name>.yaml`. Procedures go inline in the prompt up to 8,000 characters, otherwise only descriptions plus an `activate_skill` tool.
  - **Sync model:** every save is a version in D1 (`agent_configs`); the highest is live. The dashboard and `jun push` write versions; `jun pull` brings dashboard edits back to git. Dashboard saves must start from the latest version; CLI pushes only conflict with *dashboard* edits made since the pusher's last pull (git is their source of truth). `--force` overrides.
  - **Approvals (AI-06) and MCP (AI-14) stay v2** as planned; the AI SDK supports both (`toolApproval`, `@ai-sdk/mcp`) when we get there.
- **2026-10-05 — D-10 (update) — Default Workers AI model is now `@cf/mistralai/mistral-small-3.1-24b-instruct`.** With tools in the prompt, Llama 3.3 70B fixated on them (asked "dashboard won't load" and payment-bug customers for an order number) and missed escalations. Mistral Small 3.1 answered all five benchmark questions correctly, about 1 s to first word; GPT-OSS-120B was also correct and slightly more polished, 2–3 s (`scripts/bench-models.ts`, 2026-10-05). Release default provider still the user's call.
- **2026-10-05 — D-23 — Visitors and identity (M6, user: "letsgo").**
  - **Identity (V-03):** the host app's backend signs a short-lived **HS256 JWT** (`sub` required, `exp` required, optional `email`, `name`, `attributes`) with a per-workspace identity secret (Settings → Install; admins can show, rotate or turn it off). Only HS256 is accepted, never `none` or a key from the token. Rotating the secret revokes all tokens. The page passes it with `data-user-token` or `JunDesk.identify(jwt)`; `JunDesk.logout()` forgets it. Asymmetric keys (RS256/JWKS) can come later if customers ask.
  - **Merge (V-04):** browsers hold visitor tokens in a new `visitor_tokens` table (one contact, many browsers). An anonymous visitor who identifies merges into the user's contact (conversations and tokens move). A browser already identified as another user gets a fresh token instead, so one user never inherits another's history (shared computers).
  - **Attributes (V-05):** come only from the verified JWT (`attributes` claim) and replace the previous ones on each identify. The AI's prompt names a verified customer; tools can use `{user.id}`, `{user.email}`, `{user.name}`, `{user.<attribute>}` and refuse ("not signed in") for anonymous visitors. Unverified attributes from page JavaScript are not accepted in v1.
  - **Live visitors (V-01):** the loader opens one WebSocket (`/api/widget/:key/live`, any origin) to the workspace hub, which hibernates between messages. It reports page, title, referrer, session start, language and time zone; Cloudflare adds country and city. Sessions live in sessionStorage. Agents get the full list on connect, then changes. Visitor sockets never receive inbox events.
  - **Agent-started chats (V-07):** an invite (stored in `visitor_invites`, 30 min, single use) is delivered to that session's page as a card with the agent's name. Replying creates a conversation that starts with the agent's message, handled by humans and assigned to that agent.
  - **Consent (V-06):** `data-consent="required"` stores nothing (no sessionStorage, chat token in memory only) and opens no live connection until `JunDesk.consent(true)`.
  - **Loader size:** with this the readable `public/widget.js` grew past 5 KB gzipped, so the build now minifies it (`rolldown/utils`, Vite's own dependency): 4.05 KB gzipped served.
- **2026-10-05 — S-11 — The nudge is worded by the AI, not guessed from URL keywords.** The user asked how the widget "knew" a failure was a payment: it matched words like `pay`/`billing`/`card` in the URL, which mislabels e.g. `/api/cards`. Now the desk's AI writes the line from the masked failure (method, URL, status, error message, stack top, page title), with a strict output filter and a generic fallback. Reading error response bodies for more detail (S-10) is kept for later as a per-site opt-in, since it partly reverses D-19. Fixing this also exposed that the old nudge's `/config` fetch had no CORS headers, so nudges never appeared on customers' real (cross-origin) sites; the new endpoint allows any origin.
- **2026-10-05 — T-16 — Widget domain allowlist (user: "letsgo").** The widget key is public, so copies of the snippet could embed your chat elsewhere, add fake sessions to the live list and spend AI on nudges. Admins list allowed websites; browsers enforce it: the live socket and the nudge check `Origin`, and the chat frame carries `Content-Security-Policy: frame-ancestors` for the listed sites (both `http` and `https`, any port). An empty list keeps today's "any website" behaviour; the desk's own origin (demo page) always works. Same approach as Intercom/Crisp/Chatbase. Doesn't stop a non-browser script that forges `Origin`; that needs rate limiting (later).
- **2026-10-05 — D-24 — M7 launch-critical polish (user: "lets do it").** Built the four 🚀 items first; the nice-to-haves (I-05 notes/@mentions, I-06 saved replies, I-07 tags, W-08 offline email, W-12 CSAT, A-01 metrics) wait.
  - **Business hours (I-10):** stored on the widget inbox (time zone + one span per weekday + away message). The AI answers regardless; the automatic away reply goes only to conversations with the team, once per closed period (keyed by the next opening), and not when an agent replied in the last 15 minutes. Times are shown in the business's time zone ("Monday at 09:00 (London time)"), since the server doesn't know every visitor's zone.
  - **Branding (W-04):** the loader now fetches `/api/widget/:key/config` at startup (CORS `*`, cached 60 s) and stays hidden up to 1.5 s to avoid a colour flash, so branding changes need no new snippet. Text colour on the brand colour is picked by luminance. Logos are raster only (no SVG, which can carry scripts), served with `nosniff` and a locked-down CSP.
  - **Contact sidebar (I-08):** verified contacts' name/email come from the customer's app and can't be edited by agents; anonymous visitors' can.
  - **Knowledge (K-04):** removing a page adds it to the source's skip list so a re-sync doesn't bring it back.
